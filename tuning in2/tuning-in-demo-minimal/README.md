# Tuning In · 知音

> 音乐播放到哪里，问题就发生在哪里。

知音是一款面向古典乐小白的多智能体音乐陪听产品。

你可以一边播放音乐，一边向莫扎特、巴赫或贝多芬提问。系统会结合当前播放时间、曲目节点和知识库，让三位陪听者从各自熟悉的创作视角回答。

这里的音乐家形象属于产品化的聆听视角。它们参考人物史料、创作实践与音乐思想，不冒充历史人物本人，也不会虚构他们听过后世作品。

## 它想解决什么

很多音乐介绍写得很专业，第一次接触古典乐的人很难马上听懂。普通的 AI 回答又容易变成一段放在哪里都合适的文案。

知音尝试把解释落到耳朵真正能听见的地方。

- 旋律刚才发生了什么变化
- 当前这一段应该先听高处还是低处
- 为什么同一个短句一直回来
- 伴奏和旋律怎样互相托住
- 三位音乐家会从哪些不同角度理解这一刻

回答尽量使用普通语言。用户看完以后，可以马上回到音乐里验证。

## 三位陪听者

| 陪听者 | 主要观察对象 | 回答气质 |
| --- | --- | --- |
| 莫扎特视角 | 旋律、乐句、问答、转身 | 反应快，轻巧，带一点排练现场的机灵 |
| 巴赫视角 | 声部、低音、层次、结构 | 准确务实，喜欢先把每一层的工作理清 |
| 贝多芬视角 | 动机、重复、阻力、推进 | 直接有力，会追问材料为什么还要继续回来 |

三位角色不会机械套用固定性格。回答仍然以用户的问题和当前声音证据为主，人物气质只影响观察顺序、句子节奏和表达习惯。

## 可以体验什么

- 在音乐播放过程中随时提问
- 指定一位音乐家回答
- 让主 Agent 自动判断由谁回答
- 让三位陪听者围绕同一小节继续讨论
- 根据播放时间召回当前音乐节点
- 查询人物经历、创作方法与代表作品
- 查看回答使用了哪些知识和音乐证据
- 在曲目进度条下查看简短的节点提示

## 一次回答怎样产生

```mermaid
flowchart LR
    A[用户问题] --> B[主 Agent 判断意图]
    B --> C[识别曲目与播放时间]
    C --> D[检索人物和曲目知识]
    D --> E[选择音乐家子 Agent]
    E --> F[结合当前节点生成回答]
    F --> G[返回依据与聆听提示]
```

当前版本包含人物史实、人物聆听方法、作品事实、整曲路线和音乐节点等知识。知识内容已经生成 102 条向量缓存，后端会结合向量相似度、问题类型、播放时间和词面信息进行重排。

## 下载

GitHub 仓库提供一个可运行压缩包，避免网页端一次上传大量项目文件。

下载 `tuning-in-demo.zip`，解压后进入项目目录。

## 运行环境

- Node.js 22 或更高版本
- npm
- AIHubMix API Key
- 可访问 AIHubMix 接口的网络环境

## 快速开始

复制环境变量示例文件。

```bash
cp .env.example .env.local
```

打开 `.env.local`，填写自己的配置。

```text
AIHUBMIX_API_KEY=你的_API_Key
AIHUBMIX_BASE_URL=https://aihubmix.com/v1
ADMIN_TOKEN=你自己设置的管理员口令
```

安装依赖并启动。

```bash
npm install
npm start
```

浏览器打开产品首页。

```text
http://127.0.0.1:4317/index.html
```

也可以直接进入共听页面。

```text
http://127.0.0.1:4317/listening-room.html
```

检查后端状态。

```text
http://127.0.0.1:4317/api/health
```

看到 `ok` 为 `true`，说明后端已经启动并加载知识向量。

## 项目结构

```text
知音-web-deploy/          四幕产品网页与前端交互
server/                  Node.js 后端、对话编排与检索逻辑
prompts/                 主 Agent、三位子 Agent 与共同运行协议
knowledge/dify/          三位音乐家的人物知识文档
knowledge/musicians/     人物知识卡
knowledge/pieces/        曲目、时间节点与回答边界
knowledge/v2/chunks/     经过整理的知识切片
data/embeddings/         人物知识与曲目知识向量缓存
music-analysis-skill/    三首曲目的审核后分析数据
config/models.json       模型和检索参数
```

## 模型分工

| 环节 | 默认模型或方式 |
| --- | --- |
| 主 Agent 路由 | `gemini-3.5-flash-lite` |
| 音乐家子 Agent | `gpt-5.6-luna` |
| 回答兜底 | `deepseek-v4-flash-0731` |
| Embedding | `BAAI/bge-large-zh-v1.5` |
| Rerank | 播放时间、知识范围与词面特征联合重排 |

这些模型可以在 `config/models.json` 中替换。实际可用模型以你的 AIHubMix 账户为准。

## 关于音乐家口吻

知音不会输出“贝多芬本人听到这里认为”一类无法核实的话。

系统采用“受其创作实践启发的聆听视角”。人物史料负责提供事实边界，角色提示词负责区分观察方式，曲目节点负责约束这一刻究竟能听见什么。

回答应当满足三个要求。

1. 第一次接触古典乐的人能够看懂。
2. 用户看完以后知道下一遍该听什么。
3. 有音乐基础的人能够看出回答依据，没有明显瞎说。

## 媒体文件说明

公开下载包不包含演奏视频、音乐音轨和人物试听音频。这些文件的公开转载授权尚未确认。

如需完整播放体验，请准备自己有权使用的媒体文件，并放入以下目录。

```text
知音-web-deploy/assets/video/library/
知音-web-deploy/assets/audio/library/
知音-web-deploy/assets/audio/portraits/
```

三首演示曲目的默认文件名可以在 `知音-web-deploy/assets/js/listening-room.js` 中查看和修改。

## 数据与隐私

下载包不包含以下内容。

- 开发者的 API Key
- 管理员真实口令
- 本地 SQLite 数据库
- 用户聊天记录
- 服务运行日志
- 临时上传文件

请勿把自己的 `.env.local`、数据库或真实用户数据提交到公开仓库。

## 当前限制

- 模型不会直接听见音频，目前依据人工审核的曲目节点回答。
- 知识库主要覆盖莫扎特、巴赫、贝多芬和三首演示曲目。
- 新增曲目后，需要补充作品信息、聆听路线、节点证据和回答边界。
- 缺少媒体文件时，页面和智能问答仍可启动，音乐播放功能不可用。
- 这是用于产品验证的演示版本，还没有完成生产环境部署和大规模用户测试。
